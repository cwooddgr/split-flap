# Releases and deploys

> **Author:** Claude Code (coder) · **Date:** 2026-09-26 · **Status:** moved verbatim from `CLAUDE.md` when it was slimmed (decided-by-user 2026-09-26); provenance stamps inside the text are the originals.

## Web deploy

**Deploy:** `.github/workflows/pages.yml` publishes `web/`, and only `web/`, to `flipflap.dgrlabs.co` on every push to `main` that touches it (since 2026-09-20; before that GitHub Pages served the whole repo root, notes and tvOS sources included). The custom domain lives in the repo's Pages settings; the root `CNAME` file is ignored by a workflow deploy and is kept only so a rollback to branch publishing would work. `web/control.html` must keep its name and place, because the shipped tvOS app hardcodes `https://flipflap.dgrlabs.co/control.html`. Anything that should not be public on the product domain stays out of `web/`. Plain http redirects to https at Cloudflare: "Always Use HTTPS" is on for the whole dgrlabs.co zone since 2026-09-20 (decided-by-user; `itdept/changelog/2026-09-20-dgrlabs-co-always-use-https.md`), because GitHub Pages can't enforce HTTPS behind Cloudflare's proxy.

### tvOS release process

> **Author:** Claude Code (coder) · **Date:** 2026-09-21 · **Status:** the permission is decided-by-user (quoted below); the steps are proposed-by-agent and are what worked on 1.2.

Charlie, 2026-09-21, for all DGR Labs app projects (also in the workspace `CLAUDE.md` and as an `autoMode.allow` rule in `~/.claude/settings.json`): "Standing permission: in my app projects, the project's agent may submit a version to App Review through the App Store Connect API once I've told it in that session to submit that version. It never resubmits after a rejection without asking me." And, when I suggested he name the app each time he says to submit: "I do NOT want to have to name the app when I'm working in its project directory. which app should be obvious." In this directory the app is Flip Flap, and the version is the one the session has been preparing.

1. **Cut.** Read `../APP_STORE_REJECTIONS.md`. Run `node --test tests/layout.test.mjs` and `cd tvos && swift test`. Check the build numbers already on App Store Connect (they are per version on tvOS, but pick one no earlier build has used), bump `tvos/SplitFlapTV/Version.xcconfig`, commit, tag `tvos-<version>-<build>`, push.
2. **Upload.** `xcodebuild -project tvos/SplitFlapTV/SplitFlapTV.xcodeproj -scheme SplitFlapTV -configuration Release -destination 'generic/platform=tvOS' -archivePath <scratch>/FlipFlap.xcarchive -allowProvisioningUpdates archive`, then `xcodebuild -exportArchive` with an export options plist of `method` app-store-connect, `destination` upload, `signingStyle` automatic, `teamID` 2CTUXD4C44. Automatic signing goes through the Apple ID signed in to Xcode, so this step needs no API key. Keep the archive out of the repo. Wait for the build to read `VALID`.
3. **Prepare.** The API client is `node ../otd/scripts/asc.mjs <METHOD> <path> [json|@file]`. App id `6761391738`, platform `TV_OS`. `POST /v1/appStoreVersions` with the previous version's `releaseType`; `PATCH` `whatsNew` on the new version's en-US localization with text Charlie has approved (keep a copy in `APP_STORE_LISTING.md`); copy `promotionalText` from the previous version, because a new version does not inherit it (null on 1.2); `PATCH /v1/appStoreVersions/{id}/relationships/build`. The App Review contact and notes carry over. App-level text such as the Apple TV Privacy Policy lives on the `appInfoLocalization` of the app info in `PREPARE_FOR_SUBMISSION`, not the live one.
4. **Submit, once Charlie has said in that session to submit that version.** Check `/v1/apps/6761391738/reviewSubmissions` for an open submission first. Then `POST /v1/reviewSubmissions` (platform `TV_OS`), `POST /v1/reviewSubmissionItems` with the version, and `PATCH` the submission with `submitted: true`. Expect `WAITING_FOR_REVIEW`. Update the status line above with the date and state.
5. **Afterwards.** Flip Flap is not on supportbot's list and has no release-sync routine. A rejection goes in `../APP_STORE_REJECTIONS.md`, and a resubmission waits for Charlie.

The shared release guide for all our apps (order of the work, each project's recipe, App Store Connect gotchas) is `../APP_STORE_RELEASE.md`, approved by Charlie 2026-09-21; read it when cutting a build, and add to it when a release teaches us something new.
